# Этап 2.1. Доработки интерфейса, права на слоты, демо-данные
*Спецификация v1, 31.10.2026. Опирается на: `stage-2-ui-polish.md` (сырой вход), `03_matrix.md`, `stage-2-schedule.md` (разд. 5, 12). Предположения помечены `ASSUMPTION`.*

## 1. Цель, MVP-срез и метрика
Цель: принять замечания заказчика к этапу 2 (меню, права на слоты, правки страниц, демо-сид). Метрика: тесты зелёные, чек-лист осмотра (п. 6.5) пройден заказчиком.
**Must:** A1–A3, B1–B7, демо-сид C. **Не входит (Later):** этап 3 (дела, осмотры; сид под них добавляется в его DoD), CSP, кэш, статус допуска у тренера (этап 4), смена модели данных (миграций нет).

## 2. Решения заказчика
A1 боковое меню; A2 слоты создают/закрывают/открывают только admin и registrar, врач читает своё расписание; A3 роль в шапке не показывается. Тема Almanac и контракт разд. 12 `stage-2-schedule.md` сохраняются, кроме пунктов, помеченных «ИЗМЕНЕНО» ниже.

## 3. Права и ручки (RBAC)
Изменения `app/core/rbac.py` (матрица `03_matrix.md` уже обновлена):
1. `SLOT_CREATE`: `{ADMIN: F, REGISTRAR: F}` (врача нет). Гейтит все изменяющие операции со слотами.
2. Новое `Action.SLOT_VIEW` (управляемые слоты): `{ADMIN: F, REGISTRAR: F, DOCTOR: OWN}`. Гейтит чтение управляемых слотов.
3. JSON (ИЗМЕНЕНО в 12.1): `GET /schedule/slots/all` — `SLOT_VIEW`; doctor получает только свои слоты (фильтр в SQL, чужой `doctor_id` в запросе игнорируется и не раскрывает чужое), registrar/admin — любые. `POST /schedule/slots`, `/slots/batch`, `/slots/{id}/close`, `/slots/{id}/reopen` — `SLOT_CREATE`: doctor, athlete, coach получают 403, без изменений в БД и без аудита. `doctor_id` в запросе обязателен для registrar так же, как для admin (ошибка валидации как у admin сейчас).
4. Сервис слотов проверяет право по `SLOT_CREATE` сам (не только роутер): врач 403 и при вызове страницы. `ASSUMPTION`: проверка уже есть в `app/schedule/policy.py`/`planning.py` через роль; исполнитель обязан убрать ветку «врач управляет своим».
5. Аудит: действия `slot.create|close|reopen` как раньше; actor — registrar тоже; ПД не пишем.
6. Свободные слоты (`SLOT_VIEW_FREE`), запись, очередь — без изменений.

## 4. Страницы и компоненты
### 4.1 Страницы слотов (ИЗМЕНЕНО в 12.5 и разд. 5)
| URL | метод | доступ | отличие |
|---|---|---|---|
| `/cabinet/slots` | GET | admin, registrar (`SLOT_VIEW` F), doctor (OWN) | doctor: только свои слоты, ФИО записавшегося, **без** кнопок `close/reopen` и **без** формы `slot-form`/фильтра врача; registrar/admin: фильтр врача, кнопки, форма |
| `/cabinet/slots/new`, `/{id}/close`, `/{id}/reopen` | POST | admin, registrar | doctor: 403 (страница 403, не 404); чужого слота у врача больше нет как сценария |
Для registrar всё как у admin: `f-slot_doctor_id` обязателен («Выберите врача», 422), `f-doctor_id` в фильтре. Остальные id/тексты 12.5 (`slots-filter`, `slots-manage-table`, `slot-form`, `slots-result`, `e-*`, `data-status`, `data-action`) не меняются. В шаблонах флаг `admin` заменить на `can_manage`/`all_doctors` (внутреннее).

### 4.2 Боковое меню (A1) и шапка (A3, B1, B6)
1. Разметка для авторизованных страниц `base.html`: `<header>` (бренд слева, блок `#user-box`), `<aside><nav id="side-nav" aria-label="Разделы">` слева, `<main id="main">`. Гость (login, главная) без меню.
2. Пункты берутся только из `nav_links(user)` (`app/web/nav.py`); пункт: `<a href>` с текстом одной строкой «Название — описание» (название `<strong>`, описание `<span>`; в тексте ссылки « — » между ними). Описание не выносится в серый абзац. Порядок: расписание/запись, очередь, слоты, регистрация спортсмена, создание пользователя, смена пароля.
3. Текущий раздел: `aria-current="page"` на ссылке, чей `href` равен пути или является его префиксом (`/cabinet/slots/new` подсвечивает слоты); на `/cabinet` не подсвечивается ничего. Наведение: затемнение плитки (CSS, токены, без inline).
4. Узкий экран (< 900 px): меню скрыто, кнопка `<button id="menu-toggle" aria-controls="side-nav" aria-expanded>` «Меню» открывает выезжающую панель (Alpine `menuOpen`), Esc и клик по пункту закрывают, фокус возвращается на кнопку. На широком кнопка скрыта.
5. Тексты (ИЗМЕНЕНО в 12.6 и разд. 5; имена пунктов): athlete: «Записаться на приём», «Моя запись»; registrar: «Расписание и запись», «Очередь и приход», «Слоты врачей», «Зарегистрировать спортсмена»; admin: те же плюс «Создать пользователя»; doctor: «Свободные слоты», «Моё расписание» (вместо «Мои слоты»; описание «Ваши слоты и записавшиеся, только просмотр»); у admin «Слоты врачей» вместо «Управление слотами»; у всех «Сменить пароль»; coach: только «Сменить пароль». Описания — одно предложение до 60 символов, без точки.
6. Шапка: роль (бейдж/текст) не выводится нигде; `#user-box` — имя и кнопка «Выйти», отделён от бренда линией/отступом; ссылок навигации рядом с брендом нет; бренд «АвиаМед» (шапка) и «Медицинский центр МАИ» (подвал) выровнены по левому краю контента (общий контейнер, B1).
7. `/cabinet` (index): короткое приветствие по имени («Здравствуйте, Имя Отчество»), плиток нет. Coach (B7): блок `#coach-home` с текстом «Раздел со статусом допуска подопечных появится позже» и приветствием; список подопечных не показывается (`ASSUMPTION`, диагнозов и статусов нет); привязка подопечных создаётся сидом.

## 5. Демо-сид (`make seed-demo CONFIRM=local`)
Расширяется `app/seed.py` (+ `app/seed_schedule.py` для слотов и записей), CLI `seed-demo` и Makefile: цель `seed-demo` (требует `CONFIRM=local`, вызывает `python -m app.cli seed-demo --force`); `make seed` остаётся алиасом. Правило прод-защиты как сейчас: без `DEBUG=true` или `--force` код 1 и ничего не пишется; в Makefile без `CONFIRM=local` отказ.
1. **Справочники:** все виды спорта и специальности из `SPORTS`/`SPECIALTIES`; `seed-reference` этапа 3 — Later.
2. **Пользователи (минимум):** 1 admin, 2 registrar, 6 doctor (6 разных специальностей; ровно один спортврач с `can_issue_conclusion=true`, остальные false), 3 coach, 40 athlete с профилем (вид спорта из справочника, `coach_id` из 3 тренеров, поровну ±1, согласие с номером `DEMO-NNNN`). Email детерминированы: первый каждой роли `demo-<role>@example.com` (как сейчас), остальные `demo-<role>-N@example.com`, N с 2. ФИО из фиксированных списков, без random без seed. Пароль у всех `Demo12345!` (или `DEMO_PASSWORD`).
3. **Слоты:** у каждого врача на 14 дней вперёд (от завтра) и 14 назад, с 09:00 до 12:00 и с 14:00 до 17:00 по Москве, слот 30 минут. Каждый 5-й будущий свободный слот закрыт. Время хранится в UTC. Дедуп по `(doctor_id, start_at)`.
4. **Записи (минимум, по всем врачам суммарно):** прошлые: `done` ≥ 8, `no_show` ≥ 4, `cancelled` ≥ 4; сегодня: `arrived` ≥ 2, `booked` ≥ 2; будущие: `booked` ≥ 15, `cancelled` ≥ 3. Слот записи `done/arrived/no_show/booked` — `booked`; слот отменённой записи — `free`. На каждую запись `status_history` по пути из `SLOT_TRANSITIONS` (booked; +arrived; +done / no_show / cancelled) и аудит как у сервиса. Записи не нарушают инварианты: одна активная запись на слот, нет пересечений у спортсмена, активных у спортсмена ≤ `MAX_ACTIVE_APPOINTMENTS`.
5. **Идемпотентность:** повторный запуск ничего не создаёт и не меняет (пользователи по email, слоты по ключу, записи только если у демо-спортсменов их ещё нет); вывод «created/exists» и итоги по сущностям. Повторный запуск в другой день может добавить слоты нового окна, но не трогает прежние.
6. **Вывод:** логины по ролям (все сотрудники, первые 3 спортсмена, «…и ещё 37»); пароль печатается только если он публичный по умолчанию.
7. Дополнение сида под этапы 3–4 — обязательная часть их DoD (в `CLAUDE.md`).

## 6. Критерии приёмки
### 6.1 Права (pytest/httpx, `tests/schedule/`)
- R-1 registrar `POST /schedule/slots` с `doctor_id` → 201, слот у этого врача; в аудите actor registrar.
- R-2 registrar `POST /schedule/slots` без `doctor_id` → 422.
- R-3 registrar `/slots/batch` → 201; пересечение → 409 как раньше.
- R-4 registrar `close` свободного слота → 204; `reopen` → 204; занятого → 409 как раньше.
- R-5 doctor `POST /slots`, `/slots/batch`, `close`, `reopen` (в т.ч. свой слот) → 403, слот и аудит не изменились.
- R-6 athlete и coach на те же ручки → 403; без сессии → 401.
- R-7 doctor `GET /slots/all` → 200, только его слоты, с ФИО записавшегося; `?doctor_id=<чужой>` → список без чужих слотов.
- R-8 registrar и admin `GET /slots/all` → 200 со слотами всех врачей; athlete/coach → 403.
- R-9 `PERMISSIONS[SLOT_CREATE]` не содержит doctor; `PERMISSIONS[SLOT_VIEW]` == admin F, registrar F, doctor OWN.
- R-10 вызов сервиса создания слота от имени doctor → исключение доступа (403), не только роутер.

## 7. Нефункциональные требования
Миграций нет. Конкурентность: сид однопоточный; уникальность слота `(doctor_id,start_at)` и активной записи на слот держит БД, сид не обходит ограничений. Сид не пишет ПД в аудит. Производительность сида: ≤ 60 с на локальной БД (Argon2 хэш пароля считается один раз и переиспользуется для всех демо-аккаунтов — `ASSUMPTION`, допустимо, т.к. публичный пароль).
