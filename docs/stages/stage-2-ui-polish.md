# Доработки этапа 2 после осмотра заказчиком (31.10.2026)

Источник: голосовые замечания заказчика по осмотру страниц под всеми ролями. Решения заказчика зафиксированы. Тема Almanac, правила Hallmark и контракт раздела 12 `stage-2-schedule.md` остаются, если не сказано иное.

## A. Решения заказчика

1. **Меню:** постоянное боковое меню слева на всех страницах после входа (плитки с затемнением при наведении, текущий раздел выделен). Сверху остаются только бренд и блок пользователя. Плитки с главной кабинета убираются, там короткое приветствие. На узких экранах меню выезжает панелью по кнопке «Меню». Ссылки меню берутся из одного источника (`app/web/nav.py`), с описанием раздела в виде «Название — описание» в одной строке.
2. **Слоты:** создают, закрывают и открывают только admin и registrar (врач указывается в запросе, как сейчас у админа); врач видит своё расписание и записавшихся (ФИО) только на чтение. Матрица `docs/03_matrix.md` уже обновлена.
3. **Роль** пользователя в шапке не показывается (ни бейдж, ни текст).

## C. Демо-данные (`make seed-demo`)

Отдельная идемпотентная команда (CLI `seed-demo` расширить, цель `make seed-demo CONFIRM=local`; существующую `make seed` оставить как алиас), наполняет ВСЕ сущности приложения, чтобы можно было пройти по каждому разделу:
- Справочники (виды спорта, специальности) и `seed-reference`, если этап 3 уже в коде.
- Пользователи: 1 админ, 2 регистратора, 6 врачей (разные специальности, хотя бы один спортврач с `can_issue_conclusion`), 3 тренера, 40 спортсменов (с профилями, привязкой к тренерам и видам спорта, согласиями).
- Слоты: на ближайшие 14 дней у каждого врача (утро и день, часть закрыта), плюс слоты за прошлые 14 дней.
- Записи во всех статусах: booked, arrived, done, no_show, cancelled (прошлые и будущие), с корректными `status_history` и аудитом, соблюдая инварианты расписания (без нарушений уникальности и пересечений).
- Одинаковый известный демо-пароль (`Demo12345!`), вывод списка логинов по ролям; запуск только при `--force`/`CONFIRM=local`, никогда на проде; повторный запуск ничего не дублирует.
- По мере появления этапов (дела, осмотры, заключения) сид дополняется: это обязательная часть Definition of Done каждого этапа.
