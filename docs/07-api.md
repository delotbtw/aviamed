# 07. Ручки и авторизация

*Черновик v0.1, 26.10.2026. Это перечень, а не окончательная спецификация. Формат запросов и ответов уточним при реализации.*

## 1. Общие правила

- Страницы рендерятся на сервере (Jinja). Часть ручек возвращает JSON для небольших динамических действий.
- Все ручки, кроме входа и публичных страниц, требуют авторизации.
- Роль проверяется зависимостью до вызова сервиса; принадлежность данных — в сервисе.
- Ограничение частоты запросов: на уровне Nginx для всего трафика и на уровне приложения для входа (см. [08-security.md](08-security.md)).
- Ответы об ошибке не раскрывают лишнего («неверный логин или пароль», а не «пользователь не найден»).

## 2. Авторизация (JWT)

- Вход по email и паролю выдаёт пару токенов: короткоживущий access и долгоживущий refresh.
- Refresh хранится в БД в виде хэша и может быть отозван (список отозванных в Redis).
- Ориентиры: access — десятки минут, refresh — дни. Точные значения уточним при настройке.
- Выход отзывает refresh.
- Смена пароля отзывает все активные refresh-токены пользователя.
- Внешняя авторизация (OAuth) в MVP не делается. Провайдером будет внутренняя система МАИ (личный кабинет); закладываем только уникальный email как логин, таблицу внешних идентификаторов добавим миграцией при подключении.

## 3. Перечень ручек по модулям

### auth
| Действие | Кто |
|---|---|
| Вход, обновление токена, выход | все |
| Смена пароля | авторизованный пользователь |

### users
| Действие | Кто |
|---|---|
| Создать пользователя любой роли | admin |
| Зарегистрировать спортсмена | admin, registrar |
| Просмотр и правка своего профиля | все |
| Деактивировать пользователя | admin |

### reference
| Действие | Кто |
|---|---|
| Читать справочники и программы | все авторизованные |
| Править справочники | admin |

### schedule
| Действие | Кто |
|---|---|
| Список свободных слотов (по врачу, дате) | athlete, registrar, doctor, admin |
| Создать слоты | admin, doctor (свои) |
| Записаться на слот | athlete (себе), registrar, admin |
| Отменить запись | athlete (свою), registrar, admin |
| Отметить приход | registrar |

### cases
| Действие | Кто |
|---|---|
| Открыть дело | registrar, admin |
| Список дел и их статусы | registrar, admin; athlete (свои); coach (подопечных, только статус) |
| Отменить дело | registrar, admin |

### examinations
| Действие | Кто |
|---|---|
| Внести результат осмотра | doctor |
| Внести нагрузочное тестирование | doctor |
| Просмотр результатов | doctor (по делам), athlete (свои) |

### conclusions
| Действие | Кто |
|---|---|
| Выдать заключение | doctor с правом выдачи |
| Просмотр статуса допуска | по матрице прав |
| Скачать PDF | athlete (своё), doctor (выданное), registrar |

### audit и admin
| Действие | Кто |
|---|---|
| Журнал действий | admin |
| Админка | admin |

## 4. Страницы (серверный рендер)

| Роль | Основные экраны |
|---|---|
| Спортсмен | Вход, личный кабинет, запись на слоты, мои осмотры, статус допуска, скачать заключение |
| Тренер | Список подопечных со статусом допуска |
| Регистратура | Очередь на сегодня, регистрация, запись, открытие дел, отметка прихода |
| Врач | Мои приёмы, внесение результата, нагрузочный тест, выдача заключения |
| Администратор | Пользователи, справочники, расписание, журнал |

## 5. Принятые решения и что осталось

- Основное — страницы Jinja; JSON только для динамики (например, список свободных слотов).
- Формат пагинации и фильтров уточним при реализации.
