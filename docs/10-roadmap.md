# 10. Перспектива

*Черновик v0.1, 26.10.2026.*

Раздел описывает, что делаем после MVP и что закладываем уже сейчас, чтобы не переделывать.

## 1. Этапы

| Этап | Что делаем |
|---|---|
| MVP (до защиты) | Прототип на локальной машине, тестовые данные, сценарная проверка с директором медцентра |
| Подготовка к пилоту | Защита данных по требованиям (см. [08-security.md](08-security.md)): уровень защищённости, меры, согласия; консультация юриста |
| Пилот | Запуск для студентов-спортсменов, проходящих обследование в медцентре МАИ |
| Расширение | Все студенты вуза, новые виды обследований |

## 2. Технические направления

- **Очередь задач** (на базе Redis) для генерации PDF и рассылки уведомлений.
- **Уведомления**: о записи, об истечении срока заключения, о повторном осмотре. Возможные каналы: боты (например, Max или VK). Бизнес-логику под это в MVP не закладываем.
- **Внешняя авторизация** (OAuth) и вход через внутреннюю систему МАИ (личный кабинет).
- **Электронная подпись** заключений (ГОСТ Р ИСО 17090).
- **Интеграции** с системами медцентра и вуза.
- **Псевдонимизация и аналитика**: обезличенные данные для статистики (ГОСТ Р 55036-2012); прогноз рисков (ML) как далёкая перспектива, при появлении команды и данных.
- **Масштабирование**: выделение модулей в отдельные сервисы по границам модулей, если нагрузка это потребует.
- **Мониторинг и резервное копирование** боевого окружения.

## 3. Бизнес-эффект (на пилоте)

- Снижение очередей и времени ожидания (измеряется на пилоте, в MVP не замеряется).
- Прозрачность допусков для тренеров.
- Единая картина по спортсмену у врачей.

## 4. Риски

| Риск | Как снижаем |
|---|---|
| Требования к защите данных выше ожиданий | Закладываем меры с самого начала, юрист до пилота |
| Приказ изменится, справочник устареет | Справочник вынесен в таблицы и сверен с приказом 484н |
| Сервер не выдерживает нагрузку | Нагрузочные тесты, очередь для PDF |
| Медцентр не готов к внедрению | Письменный отзыв директора как результат проверки MVP |

## 5. Пилот

Пилот запускается после защиты проекта (проект сдаётся 05.11.2026); сроки и условия сейчас не фиксируем. Для проверки MVP достаточно сценарного прогона и письменного отзыва директора медцентра.
